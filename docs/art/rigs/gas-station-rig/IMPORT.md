# Gas station kit — import notes

Owner drop of **2026-08-20** (`Pixel art capabilitiesGasStationRig.zip`), committed **verbatim** at
`docs/art/rigs/gas-station-rig/`. Same art director and same house style as the
[fuel storage kit](../fuel-storage-kit/IMPORT.md), and it builds directly on that kit's grade table.

Everything below is **measured from the live rigs**, not read off a README — three of this kit's
documented names turn out to describe things that do not exist, and every one of them renders
something plausible rather than raising.

### The two prerequisites are the SAME FILES, not lookalikes

| | drop sha256 (LF) | repo blob sha256 (LF) |
|---|---|---|
| `isoSolid.js` | `f7fc9db5…b792bd` | `docs/art/rigs/deck-loop-kit/Art/isoSolid.js` — **same** |
| `fuelRig.js` | `811361ff…6df1ed` | `docs/art/rigs/fuel-storage-kit/fuelRig.js` — **same** |

A second copy of a registered global's source is the drift the repo's no-edit rule exists to
prevent, so both are gitignored and `RigCatalog` declares the registered ones as prerequisites.

> ⚠️ **Compare against the GIT BLOB, not the working tree.** No `.gitattributes` rule covers `*.js`
> and `core.autocrlf` is true here, so these files are stored LF and checked out CRLF. The
> checked-out `fuelRig.js` is **50,151 bytes against the drop's 49,454** — a 697-byte difference that
> is one `\r` per line and nothing else. Sizing or hashing the checked-out file reports a drift that
> does not exist, and "two live FuelIso versions" is a refusal, so this is the one way the check
> goes wrong.

To run the kit's own harness, materialise both locally and never commit them:

```bash
cp docs/art/rigs/deck-loop-kit/Art/isoSolid.js docs/art/rigs/gas-station-rig/rig/isoSolid.js
cp docs/art/rigs/fuel-storage-kit/fuelRig.js  docs/art/rigs/gas-station-rig/rig/fuelRig.js
```

## ⭐ The control: the sidecar is the oracle

This drop shipped **no reference sheets**, so the usual "reproduce a committed PNG byte-for-byte"
control was not available. The sidecar serves instead, and it is a stronger one.

`gameplay/gasStationRig.gameplay.json` is generated by `StationIso.gameplayAll()`. Regenerated in
the standalone V8 harness — the four rigs loaded in the declared order, stamps inserted where
`SidecarExport.stampRigSha` puts them, serialised as `JSON.stringify(obj, null, 1)` — it comes back
**byte-identical: 83,650 bytes, zero differences.**

That single result pins, at once:

- the host loads the kit faithfully (the reason a control exists at all);
- the committed JSON is **generated and was never hand-edited**;
- both stamps sit in canonical position;
- the bake's grade list is the one the sidecar describes — `['gas','diesel','mixed']`, which is not
  stated anywhere in the drop and had to be recovered;
- the reach audit reproduces: **45 checked · 42 as written · 3 repaired · 0 nulled**.

Pinned by `GasStationKitTests.The_committed_sidecar_regenerates_from_the_rigs_byte_for_byte`.

Both stamps verify against their files as served:

```

interiorDerivedFromRigSha256  42542b72f66b36a4…1139930c   rig/stationInteriorRig.js  ✓
```

## Handedness: CLOCKWISE, −45.000°/dir

Measured the only admissible way — the **un-squashed ground-plane bearing**, against `utilityIso`
(registered CounterClockwise) in ONE host, read two independent ways:

| route | ground step/dir | verdict |
|---|---|---|
| `StationIso.project()` | **−45.000000°** | Clockwise |
| island `slot0 → slot3` mounts (a real abeam pair) | **−45.000000°** | Clockwise |
| `IsoSolid.camBasis` (the shared turntable) | −45.000000° | Clockwise |
| `UtilityIso.project()` — the reference | **+45.000000°** | CounterClockwise |

> ⚠️ **The screen-space rotation cannot tell you this.** In raw screen space the two families read
> **−46.7525°** and **+46.7525°** — the *same magnitude*. A probe comparing magnitudes calls two
> opposite-turning kits identical, and eight cells of every piece come out mirrored. The trap is
> asserted in `The_turntable_steps_clockwise_and_the_screen_angle_cannot_tell_you_that` so nobody
> simplifies the un-squash away.

The kit shares the registered turntable **by identity, not resemblance**: mount positions and
`IsoSolid.proj` agree to `0.000000000 px` in x with `0.000000000 px` of dy spread across all eight
facings.

## ⚠️ Three silent-divergence traps — all in the kit's own DOCUMENTATION

All three are **recorded, not patched** (the art director's files run unmodified, ADR 0021 §5), and
all three are defended in the baker and pinned by tests that go red the day a drop fixes one.

### 1. `sCardlock` renders a KERB POST

The rig's own header table names the seventh dispenser `sCardlock`. The table key is **`sLock`**.

```js
StationIso.resolveSize('dispenser', 'sCardlock')  // => 'sKerb'
```

Rendered, it is **byte-identical to `sKerb`** — a 25×52 kerb post where a 32×63 cardlock terminal
was asked for, under the cardlock's file name, with no error. A build table copied from the rig's
documentation ships the wrong machine and reports success.

### 2. The export README's `render()` signature is wrong

The README documents `render(type, size, dir, opts)`. The rig is **`render(type, dir, opts)`** with
size in `opts`. Called the README's way the size string lands where `dir` belongs and `opts` is a
number — and it **does not throw**; it renders a kerb post.

### 3. `gameplaySections({size})` silently returns the PAY BOOTH

`README.station.md` documents `StationInterior.gameplaySections({ size })`. The rig's own call site
in `gasStationRig.js` passes a **bare string**. Measured:

```js
gameplaySections({size:'sStore'})  ===  gameplaySections('sKiosk')   // true  ← falls through
gameplaySections('sStore')         !==  gameplaySections('sKiosk')   // true
```

This one is **load-bearing**: `gameplaySections` is what writes the storefront's `SOLE` and
`INTERACT` into the sidecar. The committed sidecar is correct because the rig calls it with a
string — but any consumer following the README gets the pay booth's sales floor inside the C-store.

### The asymmetry underneath all three

An unknown **type** throws. An unknown **size** does not — it resolves to the type's first key. So
the only honest size check is that a size **resolves to itself**, which is what
`GasStationSheetBaker.AssertKnown` does.

## ⭐ What this rig does NOT have: the fuel kit's phantom-state defect

The fuel kit's worst trap was an omitted `wear`: the streak passes read `o.wear` raw while
`wearPass` and the cache key normalised it, so an omission rendered a fourth image and stored it
under the default's key — and whichever call ran first won for the session.

**That does not reproduce here.** `resolve()` funnels every option before both `wearPass` and the
geometry-cache key, and `skey` is built from the resolved spec rather than raw `opts`. Measured
across **all 21 pieces in BOTH call orders** (omitted-first and explicit-first, separate processes):
identical pixels, identical cells, no order dependence.

One related non-finding, so nobody hunts it: `resolve()` produces `seed` but **nothing reads it** —
the only randomness is `mulberry(type.length*613 + size.length*79 + …)`, which does not depend on
it. `seed` is an inert option, not a phantom state.

The baker still passes every option explicitly. That costs nothing, and the day a drop changes the
funnel it is the difference between a red test and a poisoned sheet.

## The seam: shell and room share ONE cell

Measured at both storefront sizes — quad **and** pivot:

| | shell `cell('store', size)` | room `StationInterior.cell(size)` | same |
|---|---|---|---|
| `sKiosk` | 252×216 @ (126,134) | 252×216 @ (126,134) | ✓ |
| `sStore` | 560×435 @ (280,254) | 560×435 @ (280,254) | ✓ |

That identity is what lets the two sheets **crop to their own ink independently** — the room's is
34–47% smaller than the shell's — and still register to the pixel, because they are aligned by a
shared world pivot and not by a cell corner.

**Interiors ashore do not move.** There is no `rock()` on this rig, and that is a law of the kit
rather than an omission. Pinned, so nobody adds one by analogy with the boat interiors.

## The facing fold — a fold, not a decimation

Islands and canopies are **180°-rotationally symmetric**, so only four facings need baking and the
presenter reads cell `dir % 4`.

| piece | pixels differing between `d` and `d+4` | of | worst |
|---|---|---|---|
| canopy `sB2` `sB3` `sB4` | **0** at every pair | 107,802 – 221,695 | byte-identical |
| island `s1` | 2 | 24,288 | 0.008% |
| island `s2` | 4 | 57,800 | 0.007% |
| island `s3` | 2 | 105,860 | 0.002% |
| island `s4` | 2 | 168,000 | 0.001% |

> ⚠️ **A hash comparison talks you out of this.** By hash the islands read as 5-distinct (`s1`–`s3`)
> and 8-distinct (`s4`) and the saving looks unavailable. The differences are one to four pixels of
> tens of thousands — the rasteriser breaking a tie on a symmetric kerb. Believing the hash costs
> 12.5 MB of duplicate art. `Fold180TolerancePixels = 4` is the measured worst case and is a
> tripwire, **not a tuning knob**: a piece that exceeds it is genuinely asymmetric and must go back
> to eight facings.

> ⚠️ **`RigBaker.DirForCell(cell, 4, …)` is the WRONG call here.** It means dirs 0·2·4·6 — a
> decimation, four snapped quarters — which on a 180°-symmetric piece renders only **two** distinct
> pictures and throws away half the angular resolution for nothing. The fold wants dirs 0·1·2·3, one
> per equivalence class, so the baker asks for the eight-facing dir of the first four cells. Under
> either convention that is a complete set of representatives.

### Packing, not a lifted cap

`store_sStore` cropped is 556×431. Laid out as one strip of eight that is **4,448 px wide**, well
over the 2048 import cap — and a sheet between the cap and Unity's hard limit **bakes fine and then
imports silently downscaled with the sprite count still correct**, which poisons every slice rect.

So sheets are **grid-packed**: `GasStationKit.Columns()` takes the widest layout that fits on both
axes, which leaves most pieces as the familiar single strip and folds only the big ones into rows.
`store_sStore` and `interior_sStore` come out 2 columns × 4 rows. Nothing needed the cap lifting the
way `ShopKit` does (4096).

## Running the rigs without Unity

The standalone V8 harness ([[run-rigs-in-standalone-v8-harness]]) runs all four files unmodified in
the repo's own ClearScript — seconds per render instead of a 20-minute batch. Load order is
`isoSolid → fuelRig → gasStationRig → stationInteriorRig`; each throws by name if its predecessor is
missing, so a wrong order fails loudly.

Guards worth porting, because the harness that skips them renders the wrong thing silently: assert
all four globals installed, and assert the rig publishes **21** pieces before believing any
measurement.

## Vocabulary

**Pieces (21).** `dispenser` ×7 (`sKerb` `sVintage` `sDock` `sTwin` `sMpd` `sTruck` **`sLock`**) ·
`island` ×4 (`s1`–`s4`) · `canopy` ×3 (`sB2` `sB3` `sB4`) · `sign` ×3 (`sPylon` `sTotem` `sAframe`) ·
`store` ×2 (`sKiosk` `sStore`) · `fillport` ×2 (`sCluster` `sVent`).

**Grades — the fixed contract the economy lane builds against:**
`gas` · `diesel` · `mixed` · `oil` · `stove_oil`. The rig's internal key for the last is `kero`;
`GasStationKit.GradeId()` is the one place that maps it.

**Hoses are never baked.** `StationIso.serve(outlet, target)` returns a runtime polyline plus honest
metres, and slack grows as the pull shortens. Nothing in the sheets draws a hose.
