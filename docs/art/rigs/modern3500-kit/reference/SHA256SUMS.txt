# Re-issued 2026-09-16: the rig folds its palette 27 ramps -> 16; the contract and the ten sheets
# were re-baked on node from that rig. At intake its exported literal gained KEY, GAIN, BIAS, LN,
# build (one line), and the three stamps moved to the digest of those bytes.
#
# Re-issued 2026-09-18 on OUR side, by the owner's ruling D1 ("Badge off"): the rig's two 'RAM'
# lettering draws were cut with nothing in their place (faces 2802 -> 2738, triangles 6856 -> 6728).
# The contract's `rigSha256` and the sidecar's `derivedFromRigSha256` were re-derived from the cut
# rig's bytes in the same commit, and the five text digests above were recomputed (the sidecar was
# also re-keyed to the fleet schema, and the README records the rulings). The ten sheet lines are
# unchanged: the sheets were not re-baked, predate the cut, and stay reference only. This is NOT the
# refusal case at the foot of this file -- the rig moved HERE, under a ruling, and its stamps moved
# with it. But the upstream Codex drop still draws the lettering, so a regeneration taken from
# upstream brings the badge back: the D1 cut has to go upstream before one is re-taken.
#
# ../modern3500.rig.js's digest above is ALSO modern3500.contract.json's `rigSha256` and the gameplay
# sidecar's `derivedFromRigSha256`. All three were verified equal on the delivered bytes and again
# after the copy into the repo. Compare the FULL 64-char digest, never a prefix: the hightop van's
# bad stamp shared its rig's first SIXTEEN hex digits and diverged over the remaining 48, and a
# prefix check is what let it through.
#
# Text hashes are over LF bytes. Unlike the ATV pack, that needs no conversion step here: the five
# text files are pinned `text eol=lf` in .gitattributes BY NAME, so the working-tree form is the
# blob form on every platform and `sha256sum -c SHA256SUMS.txt` runs as-is from this folder. The
# pin is named per file rather than `modern3500-kit/**` on purpose -- a blanket would also match the
# sheets below, where `text eol=lf` overrides the `-text` inside [attr]lfs and corrupts them.
#
# The ten sheets ARE listed, unlike the ATV pack's, because each digest is also the file's Git LFS
# oid: `git cat-file -p HEAD:<path>` on a pointer-only checkout prints `oid sha256:<the same 64>`.
# So these lines are checkable two ways -- against the pulled binary with `sha256sum -c`, and
# against the pointer without ever fetching it. On a checkout that has NOT run `git lfs pull` the
# `-c` form will fail these ten lines, and that is the pointer, not a corrupt sheet.
#
# The sheets are REFERENCE ONLY: this body bakes as MESH (ADR 0035, the road fleet's path) and no
# sprite path consumes them.
#
# If the rig moves and the contract's and sidecar's stamps do not, the sidecar is STALE: do not read
# its geometry, and do NOT re-stamp it here. docs/art/rigs/** is the art director's lane; a hash
# corrected on our side comes back wrong on the next regeneration and fakes freshness. Register the
# refusal in VehicleRigFleet.SidecarHashRefused and send the re-stamp upstream.
