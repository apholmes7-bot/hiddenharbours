# Content validation coverage and gaps

Audit refreshed against `d46bde303e6aa256d23d47a05ede5d7d6f38e51e`, including the validation changes in this branch. This is a source audit, not an EditMode execution report. Existing assets, appearance, configuration and save formats are unchanged. The aim is to protect the working coast (P3) from broken content additions. This document incorporates and supersedes the audit in PR 1444.

Since the first audit at `f1b4ab2`, main added four identity-bearing types (`IslandLedgerDef`, `IslandStoreShelvesDef`, `ShopShelfSlotsDef`, `ShoppingBagDef`) and 24 identities. The combined ledger now contains 2,436 identities across 177 declared types. Their explicit semantic prefixes are `islandledger`, `islandshelves`, `shelfslots`, and `shoppingbag`; the new inner-voice lines use the existing `innervoice` policy. The 66 exact legacy format exceptions are unchanged. These additions are content already on main, not exceptions to the ID rule.

## Implementation boundaries

The implementation extends `ContentValidationTests` and `Food/RecipeContentValidationTests`, and reuses the public type selector in `DefIdentityContractTests` without changing it. Exception lists remain test-only and exact (type, GUID and ID where applicable); stale entries fail so a fix removes its exception. No IDs, assets or frozen-ledger rows are changed.

The 66 format departures are: 23 route IDs, 16 light IDs, nine lot IDs, nine yard IDs, three commons IDs, three relationship IDs, two conversation IDs and one beach ID. This count comes from the committed ledger plus additions, not a Unity import. The related identity suite remains responsible for proving the inventory matches loaded assets.

Native type discovery, imports, scene wiring and the EditMode pass remain unverified here. Text and source inspection cannot establish buyer reachability or visual correctness. The new shelf, ledger and sold-out data also have dedicated tests in `Economy/IslandStoreLedgerTests.cs`, `Economy/IslandStoreShelvesTests.cs` and `IslandSupply/`; those domain checks complement the generic identity/reference sweep. The first-week and limited-licence designs do not introduce a generic buyer registry or alter this audit's ID exceptions.

Further work should keep extending existing test suites rather than replacing them: additions belong in the existing `ContentValidationTests` harness so its reflected inventory stays authoritative, and recipe changes belong in `Food/RecipeContentValidationTests`. Never normalize IDs in assets or modify the frozen identity ledger.

No local EditMode execution was performed for this audit.
