S0 spike — the EXTERIOR HALF of ADR 0038's interior swap on a mesh hull
=======================================================================

WHAT THIS IS. The measurement run behind `docs/design/boat-interior-exterior-half.md`.
BoatInterior (#622) swaps two layers — the exterior's interior-facing draw off, the baked
interior sheet on — and on the mesh path (ADR 0022) there is nothing obvious to hand it as
the exterior half, because the house is geometry rather than a sheet. The spike measures the
candidates instead of arguing about them, and STOPS: an exterior cull is an art/mesh contract
change and the coordinator rules on it.

RUN IN A CLOUD CONTAINER: no Unity, no LFS objects. So this is a SOURCE-LEVEL spike, and it
says so wherever that limits it (see WHAT COULD NOT BE MEASURED below). Two things turned out
to be measurable here anyway, and both are direct rather than inferred:
  * the committed hull meshes — `*.asset` is `unity-yaml` in .gitattributes, NOT lfs, so the
    real bake is readable text (section 0b);
  * the rigs — pure JS with no DOM dependency on these paths, so they render in node's V8.

HOW TO REGENERATE:  node docs/art/proofs/_boatInteriorExteriorHalfProof.mjs . <outdir>
Node 22 (V8). No dependencies. Run without <outdir> for the measurements alone.

WHAT IT RUNS. The rig files VERBATIM in node's V8 — the same engine ClearScript gives
RigMeshExtractor and BoatInteriorSheetBaker — so every pixel below is the rig's own
rasteriser, not a re-implementation of it. Two edits are made to the loaded text, both the
same edit RigMeshExtractor already makes for the same reason: the export literal is WIDENED
so closed-over symbols (F, _paint, projVert, camBasis) come out, and F.push is wrapped to
record which SOURCE LINE built each face. That recorder is the ground truth for "does the
face list carry an identifiable house group?" — the grouping exists in the JS and is gone by
the time the extractor has read `Global.F`.

⚠️ THE TRANSFORM IS PROVEN INERT TO THE RENDER, not assumed (section 0a): the pristine rig
and the harness-loaded rig are compared byte for byte at all 8 facings on every run. The
recorder only hangs a `__line` property on each face object, which the rig's own `_paint`
never reads. If that check ever fails it says so in place of the numbers.

DETERMINISM: two independent runs produced identical logs and byte-identical PNGs
(verified 2026-08-21; sha256 A fe5a20bd…, B ac8856cb…).

WHAT COULD NOT BE MEASURED HERE, named rather than guessed at:
  * Anything needing the compiled game — no Unity in this container, so no EditMode or
    PlayMode run, and no compile against Unity assemblies. The runtime behaviour of a cull is
    therefore ARGUED from the source and MEASURED only in the rig's own rasteriser.
  * The baked interior SHEETS (Assets/_Project/Art/Boats/Interiors/*.png) are LFS pointers
    here, so no shipped sheet pixel was read. Every interior pixel below is re-rendered from
    boatInteriorRig.js, which is the same renderer BoatInteriorSheetBaker drives — pinned by
    BoatInteriors.json's own interiorRigSha256 — but it is a re-render, not the shipped bytes.
  * How the facet shader behaves with a cull applied: not run. No GPU, no Unity.
  * Only the lobster boat was rendered end to end; the per-level finding was cross-checked on
    the side dragger and stern trawler. The other 21 cleared hulls were not rendered.

WHY THE PNGs ARE NOT COMMITTED BESIDE THIS LOG. They were rendered and reviewed, and they
belong in LFS like every other .png in this folder -- but the session that produced them had
no git-lfs binary available, so the objects could not be uploaded and committing the pointers
alone would have left a branch nobody could check out. The regenerate command above is one
line, needs no dependencies and is deterministic, so the images are a command away rather
than lost. (Same situation, same answer, as character-clip-proof-log.txt records.)
