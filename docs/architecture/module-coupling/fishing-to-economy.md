# Fishing → Economy: bait profiles and landing permission

Audited base: `12bc04b19a2efb33e352b4eea58104f7a5599be1`. Documentation only; proposed contracts below do not exist at this base. See the [audit index](README.md) for scope and relative priority.

**Carried-goods priority: medium.** This is the sole concrete feature-to-feature assembly edge, and a recorded exception rather than a newly discovered assembly violation. Removing it helps keep catch acquisition and later physical bait supply behind Core. It does not by itself repair hold unloading, delivered-only sales, or authoritative item locations. The first manual hold-to-counter route can use existing Core seams before this cleanup; the complete acquisition conversion must preserve the licence decision and bait expenditure when it changes hand/storage handling.

## Existing seams and the replacement proposal

Existing Core contracts already carry much of the flow: `ILicenseService` holds owned licence ids; `IHold`, `ICatchHands`, `CatchItem`, `FishCaught`, and `CatchLanded` carry catch state or outcomes. They do **not** provide a bait profile catalog or the species-to-licence policy. A reference through `GameServices.Licenses` does not remove the concrete `LicenseDef[]` argument of `MayLand`.

| Proposed Core seam | Implementer and consumers | Required semantics |
|---|---|---|
| `IBaitCatalog.TryGet(baitId, out BaitProfileView)` | Economy adapts the existing authored `BaitDef` assets; Fishing's rod/trap/deck code consumes the catalog. App supplies the implementation. | Read-only stable id, display text and read-only favoured species ids. The fishing query exposes no price or catalog mutation. Unknown id has an explicit result; it must not silently turn known baited traps into unbaited traps during migration. |
| `ICatchLandingPermission.Evaluate(speciesId)` returning a typed permission result | Economy owns the licence data lookup and uses existing Core `ILicenseService`; Fishing asks the Core interface immediately before acquisition. App wires the adapter. | Preserve the current authored species-to-licence mapping, ungated species, and refusal with no acquired catch. Distinguish missing catalog/configuration from a genuinely ungated species. Do not add a second required-licence field to fish data. |
| `IBaitStock` read/spend contract, with typed success/refusal | An adapter initially fronts the existing abstract stock; Fishing requests the expenditure at the existing configured moment. Physical goods authority replaces that adapter only in the approved supplies phase. | Preserve `GameConfig.BaitSpentOnCatchOnly`, exact one-bait expenditure, and the distinction between a fresh set and a pot already baited on deck. No price or new stock quantity is introduced by removing an assembly edge. |
| The proposed ADR 0055 `IGoodsTransfer`/container contracts | Mechanics owns the transaction; Economy supplies bait profile/preservation policy through Core. Rod/deck consumers submit a reachable, selected source when physical supplies are implemented. | A future physical bait move identifies the actual source item/container and revisions. It cannot be represented by decrementing an arbitrary global list while pretending the bait travelled. This is GH-09/M2 work, not permission to ship it in the bounded M1 repair. |

These are proposed interface shapes, not approved public APIs or new systems implemented here. Prefer a synchronous query/command result for permission, stock and transfer. EventBus is unsuitable as the only acknowledgement of a successful spend: handler isolation allows another subscriber to fail or be absent. Existing `CatchLanded`, `FishCaught` and `TrapPlaced` report their existing completed outcomes. A future `GoodsMoved`/`BaitConsumed` notification should follow the authoritative commit and include identity/revision information; it must never own the only inventory copy or trigger a second spend.

The safest migration leaves the original Economy ScriptableObject assets, meta GUIDs, stable ids, prices, lot sizes, species preference lists and licence data intact. Introduce the Core adapter and wire it in App first. Replace Fishing's serialized concrete fields and configuration signatures through a separately reviewed authoring migration; do not rename/recreate the assets or substitute `object`/`MonoBehaviour` plus a concrete downcast. Saved trap bait ids still resolve to the same content. Once the five consumers and their composition callers use the new contract, remove the Economy reference and the exact exception in the boundary guard together. Merely deleting the asmdef reference first leaves uncompilable fields and signatures.

## Review and proof plan

The source audit searched all runtime C# under the assigned feature modules, checked their asmdefs, inspected the five import sites and the qualified NPC bait field and foreign type/member uses, and read the existing boundary guard. No Unity, compilation or gameplay tests were run; no plate or save compatibility result is claimed.

For the implementation, preserve and extend the existing test families rather than treating their presence as proof: `FishingLicenseGateTests` covers licensed/unlicensed and ungated landing; `Economy/LicenseTests` covers mapping/wallet behavior; `PlacedTrapRuntimeTests.SaveLoad_YieldsIdenticalCatchList` covers reconstruction; `Place_ConsumesOneBaitFromStock` pins exact expenditure; `PotStockGatingTests` distinguishes fresh and pre-baited placement; `DeckPotStateTests` pins deck outcomes. Verify authored bait/licence GUID and stable-id continuity, byte-for-byte unchanged tunables, and identical deterministic catch output under the adapter. Add explicit missing-catalog/unknown-id cases with the chosen typed policy. When hand-first acquisition replaces direct hold landing, migrate the old assertions to exact hand occupancy, unchanged destination on refusal, no duplicate events and conserved identity; do not delete or loosen those assertions.

Lead-architect owns Core contract review and eventual save boundary changes; gameplay-systems owns the six Fishing consumers; economy-sim owns profiles and licence policy; App composition and content authors own wiring/serialization migration. This audit grants no scene, asset, look, price or save-format edit.
