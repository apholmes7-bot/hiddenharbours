## Scope, evidence and ranking

[Rule 7](../../CLAUDE.md) requires a 60 fps desktop target, slow heavy simulation and no per-frame HUD allocations. This supports P1's readable sea and P3's working coast without changing the established [phase](../roadmap.md) or [canon](../vision-and-pillars.md).

This is static triage, **not a measured list of the slowest frames**. Rank reflects recurring source-evidenced allocation, fan-out and plausible cache/discovery waste. There are no invented milliseconds, bytes/frame, instance counts in shipped scenes, GPU costs or claims that the game exceeds its frame budget. A profiling fixture's suggested population is a proposed workload, not a changed content budget. Source links and line numbers refer to the baseline above.

- `allocation` identifies explicit strings, arrays, reference objects, captures or collection growth on the stated branch. A struct `new`, retained buffer, list-overload lookup or native API call alone is not proof of managed allocation.
- `heavy`/`scan` identifies size-dependent work to measure. The candidates for slower/event-driven work are stable derived data, content validation and discovery. Input, physical forces, clock-derived positions, visible pose, waves and UI animation retain their cadence unless separately justified and, for art, proven unchanged.
- `gated` records an existing timer, dirty, input or state boundary. Startup/transition growth is recorded separately from a warmed steady loop. `bounded` means the inspected work is fixed/bounded, not a guarantee about all engine calls or event subscribers.
- Helpers reached from each callback were followed for relevant loops, formatting, scene/component discovery and rebuilds. Delegate targets, event subscribers, Unity internals, worker threads and GPU work are not closed-world allocation proofs. Direct LINQ/string/boxing/new-collection/GetComponent searches served as leads; the classification follows the reachable path and its gates, not keyword counts.
- Fifteen callback declarations under `Assets/Tests/PlayMode` are test-only probes and excluded from player costs; no callbacks were found in Packages. Tools has zero declarations. Three Art callbacks are editor-only in their bodies; developer demo/install callbacks are retained and labelled, not assumed absent from builds. Assembly/package/generated engine code and non-callback event/coroutine entry points are outside this census unless reached by a listed callback.
