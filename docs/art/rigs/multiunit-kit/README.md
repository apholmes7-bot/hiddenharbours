# Multi-unit building kit — terrace · walk-up · stacked flats

The art director's multi-unit housing rigs, their sixteen gameplay sidecars and the contract they were
written against, as the drop of 2026-09-17 delivered them. **Every file in this folder except this README
and [`IMPORT.md`](IMPORT.md) is the drop's, byte for byte**: each phase's `SHA256SUMS.json` lists those
bytes, and every sidecar stamps five of them. Do not edit a rig, a sidecar or a phase README here (the
rigs README's rule). A changed rig comes back as a new drop with its sidecars regenerated by
`MultiunitKit.all()`. Until then `MultiunitKitIntakeTests` fails and names the file.

The drop shipped each phase as a self-contained `<phase>-rig-kit/`, with its own copy of the five shared
rigs under `rigs/` and its own `CONTRACT.md`. One copy of each landed, so the paths written inside the
verbatim files are still the drop's. From a phase's folder here:

| The phase kit says | Here |
|---|---|
| `rigs/<phase>…IsoRig.js` | `<phase>…IsoRig.js` (same folder) |
| `rigs/_multiunitKit.js`, `rigs/_buildingGameplay.js`, `rigs/_interiorPlacer.js`, `rigs/_sidecarExport.js` | `../shared/` |
| `rigs/interiorPropRig.js` | `../../interiorPropRig.js` |
| `CONTRACT.md` | `../CONTRACT.md` |
| `README.md`, `gameplay/…` | unchanged |

That map is also how to read the keys of each `SHA256SUMS.json`. The sidecars, the rigs and the READMEs
name files as `Art/<file>.js`. There is no `Art/` folder here: resolve those by file name.
[`IMPORT.md`](IMPORT.md) §6 lists every path the phase READMEs quote and where that file is now.

## The three phases

| Phase (the sidecars' `phase`) | Shell rig | Unit rig | Presets |
|---|---|---|---|
| multi-unit phase 1 — the terrace | `rowhouseIsoRig.js` · `RowhouseIso` | `rowhouseUnitIsoRig.js` · `RowhouseUnitIso` | `millRow4` `duplexPair` `coastalRow4` |
| multi-unit phase 2 — the walk-up block | `walkupIsoRig.js` · `WalkupIso` | `walkupUnitIsoRig.js` · `WalkupUnitIso` | `walkup8` `walkup12` `walkup12Fam` `walkup4` `cannery12` `cannery8Loft` |
| multi-unit phase 3 — the three-decker stack | `stackFlatsIsoRig.js` · `StackFlatsIso` | `stackUnitIsoRig.js` · `StackUnitIso` | `decker6` `decker3` `decker4` `deckerMixed` `captains6` `captains2` `captains4` |

Each preset has one sidecar, `<phase>/gameplay/<shell stem>.<preset>.gameplay.json`. All three unit rigs
furnish with `PropIso` and write their sections through `BuildingGameplay`. The walk-up and the stack
place furniture with `InteriorPlacer`. The terrace does not: it still carries its own placement code
(IMPORT.md §5, §7).

## Checking it

The five-hash table is in IMPORT.md §3, and how the generator was re-run headless on node is in §4. The
guard is `MultiunitKitIntakeTests` (EditMode). It re-hashes the committed files against every sidecar's
stamps and every `SHA256SUMS.json`, and holds the sidecars to the contract clauses the game will rely on.
IMPORT.md §10 lists its tests, what they cannot see, and the commands that re-check the rest by hand.
