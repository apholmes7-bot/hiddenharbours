# Totes, vehicles and machines

**Design only.** Existing vehicles are real, but cargo handling on them is proposed. [ADR 0035](../../adr/0035-vehicles-module.md) keeps `Vehicles` Core-only. The new hand cart, shore tractor and forklift are briefed below; this PR does not author rigs, import meshes, change scenes or add machinery code.

## What main provides

Two rig sources were read before writing the charters: [Dually source:2–32,419–431,623](../../art/rigs/dually-iso-kit/vehicleIsoRig.js#L2) and [ATV source:1–45,670–734](../../art/rigs/atv-pack/atvIsoRig.js#L1). Their [Dually kit](../../art/rigs/dually-iso-kit/README.md) and [ATV kit](../../art/rigs/atv-pack/README.md) establish metric axes, independent articulation, posed anchors and explicit absences. [Road Fleet kit](../../art/rigs/road-fleet-kit/README.md) covers box trucks, vans, semi-tractors and trailers; these are not all pickup beds. `VehicleRigFleet` registers the families, including the modern pickup variants [registry](../../../Assets/_Project/Code/Tools/Editor/RigBaking/VehicleRigFleet.cs#L1950). `RoadFleet*` acceptance tests cover existing bake/drive geometry; their names do not prove an implemented goods system.

The runtime is `VehicleDef` / `VehicleMeshDef`, `VehicleController`, `ParkedVehicle`, `VehicleDoors`, `TowedBody`, `ParkedTrailer` and `ScheduledTrip`. Towing geometry and speed/acceleration/braking/coast factors already exist. `VehicleDef.MassKg` is kerb mass, not a cargo payload allowance; its towing factors explicitly describe feel, not a physical cargo model [VehicleDef:45–113](../../../Assets/_Project/Code/Vehicles/VehicleDef.cs#L45). `Core.VehicleSteeringMath` exposes the suspension correction that must also move cargo [VehicleSteeringMath:202](../../../Assets/_Project/Code/Core/Vehicles/VehicleSteeringMath.cs#L202). None of these establishes item inventory, load approval or unloading.

## Manual loading and unloading

1. Park and secure the carrier. Reach the correct open gate/rack with a light carried container. Core validates actor, container, mount revision, physical opening, supported slot, total mass and restraint compatibility.
2. E **“Load the pail”** changes the container's support parent from hands to one metric bed/rack slot. The fish remain children of that pail. The container base touches the posed support surface; no gap at compression or on a slope. The operator cannot load while also driving or pushing another carrier.
3. Close/latch/secure as required by its Def. A load that needs restraints cannot depart unsecured. First carrier slice blocks incompatible placement or an unsafe stack; it does not simulate random cargo falls.
4. Drive using existing input and towing behaviour. Cargo follows heading, suspension and trailer articulation through a Core support frame, and retains its cold chain. Render sort/depth follows the actual load's support/occlusion, not a blanket “always in front”.
5. Park, open and approach the load. E **“Take the pail”** moves that container into eligible hands. If now too heavy, take individual contents through reachable openings into a pan/pail, or return with a compatible cart/device. No remote unload from the driver seat.
6. At a buyer, set down a delivery in the receiving zone; mere truck proximity authorizes no sale. M2 container consignments must have a defined receiving footprint and keep the emptied player container; sale cannot consume the tote as if it were a fish.

All movement/sale commands use [the proposed Core contracts](04-first-slice.md#core-boundary-handoff). gameplay-systems implements vehicle/carry mechanics; economy-sim owns sale and preservation policy; lead-architect owns save/transaction boundaries; world-content authors accessible loading/receiving sites; ui-ux owns offers. Vehicle code never searches Boats, Fishing or Economy for a concrete item list.

## Ladder and rig handoffs

- **First new carrier: hand cart, M2.** Roll two light small containers or an approved stack in a low supported bed. Load/unload by hand; a cart does not let hands lift a filled 450 L tub. Push uses both hands; release the handle before loading. [Hand-cart rig charter](../../art/rigs/charters/hand-cart.md).
- **Existing pickup/ATV cargo, M2 after cart.** Same container/location model, measured per-rig mount and restraint facts. This is cargo integration, not another fleet art pass. Start with one model and one supported route, then add Def profiles.
- **Shore tractor and trailer, M3 by default.** A compact farm/yard tractor, distinct from the already-built road semi-tractor. Pull a small shore trailer; do not add a loader until its own fork/bucket contract is commissioned. Haul full tubs only once a real loading device and accessible sites exist. [Tractor rig charter](../../art/rigs/charters/tractor.md).
- **Forklift/pallet jack/wharf hoist, M3 before industrial tub handling.** Each needs compatible fork pockets, clearance or lifting points. Forklift rear steering and load centre differ from a pickup. A jack rolls on hard standing, a hoist changes elevation, and a forklift does both within its authored envelope. [Forklift rig charter](../../art/rigs/charters/forklift.md). Jack/hoist get separate briefs when scheduled; their appearance is not authorized by this proposal.
- **Staffed handling, M3; freight networks, M4.** Workers perform the same validated moves. Later abstract routes preserve goods in transit with departure/arrival events and elapsed game time; they do not copy cargo to its destination while also leaving it aboard.

Per-machine adoption is gated by a supported real route, measured payload and capacity data, persistence, manual recovery and art-role proof of contact/occlusion. No carrier gets to levitate over absent ground or acquire a load beyond its supported envelope. Rig charters propose new geometry; they are not approval to alter an existing asset's look.
